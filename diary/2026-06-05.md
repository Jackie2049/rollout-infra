## 16:00 — RTX 4090 全面 Benchmark 实测 (5 个实验)

**重大突破**: 终于在真实高性能 GPU (RTX 4090, CUDA 12.8) 上运行全面 benchmark！之前很多实验都是在 A16 (10 SM, CUDA 11.7) 上跑的模拟版本。

**Benchmark 实测结果 (5 个实验):**

### Exp1: FlashAttention (SDPA) vs Naive Attention
- **SDPA 峰值**: 162.3 TFLOPS @ B=1, S=8192
- **加速比**: 3.4x (S=256) → 8.5x (S=2048), 序列越长加速越大
- **对比 A16**: A16 SDPA 峰值 ~14.7 TFLOPS, 4090 是 **11x**
- Naive attention 在 B>4 或 S>2048 时 OOM (O(N²) 内存)
- SDPA 即使在 B=32, S=8192 也不 OOM (O(N) 内存, FlashAttention tiling)

### Exp2: CUDA Graph
- **加速**: 仅 1.02x (RTX 4090) vs 5.4x (A16)
- **Launch 开销**: ~1.1 us/op (4090) vs ~34 us/op (A16) — **30x 更快**
- **结论**: RTX 4090 kernel launch 本身极快, CUDA Graph 收益不大
- CUDA Graph 主要在低端 GPU (高 launch 开销) 或超多小 op 场景有收益

### Exp3: Multi-Stream 重叠
- **4x GEMM 4096²**: 0.93x (并行反而略慢!)
- **原因**: 单个 4096² FP16 GEMM 已占用全部 128 SM, GPU 饱和
- **对比 A16**: A16 双 stream 也是 0.75x (10 SM 太少)
- **结论**: Multi-stream 需要更小的 kernel (如 decode matmul), 大 GEMM 无收益

### Exp4: Batch Decode 吞吐曲线
- **峰值**: 529K tok/s @ B=512, 138.7 TFLOPS
- **线性扩展**: B=1→64 几乎完美线性 (3.3K→207K tok/s)
- **饱和点**: B≥128 开始偏离线性, B=512 达峰
- **对比 A16**: A16 峰值 ~50K tok/s @ B=16, 4090 是 **10.6x**
- Batch=1 仅 3.3K tok/s (利用率 <1%), 再次验证 Continuous Batching 必要性

### Exp5: KV Cache 分析
- RTX 4090 (24GB): 7B 模型可服务 2344 并发请求 (seq=512)
- 70B 模型 seq=32768: KV Cache 需 85.9 GB (远超 24GB), 需 offload/量化
- Block size=16: 75,000 blocks 可用 (80% VRAM 给 KV)

**关键对比 (RTX 4090 vs A16):**

|------|----------|-----|------|

## 22:00 — DPO 训练实战 (Pretrain → SFT → DPO 完整管线)

**从零实现 DPO 训练管线**: 继 pretrain+SFT 之后, 完成第三步对齐训练

**DPO (Direct Preference Optimization) 核心**:
- 将 RLHF 转化为简单的分类问题, 无需 Reward Model 和 RL 循环
- 只需 2 个模型 (policy + frozen reference), PPO 需要 4 个
- Loss: -E[log σ(β * (log_ratio_chosen - log_ratio_rejected))]

**RTX 4090 实测结果**:

### DPO 训练 (β=0.1, 20 epochs)
- Loss: 0.62 → 0.14
- Preference Accuracy: 64.9% → **99.7%**
- Reward Margin: 0.26 → 2.49
- Throughput: 229K tok/s
- Peak Memory: 295 MB

### β Sweep (5个实验)
| β | Accuracy | Margin | 结论 |
|---|----------|--------|------|
| 0.05 | 94.8% | 1.51 | 过于温和 |
| 0.10 | 96.5% | 2.55 | 标准设置 |
| 0.30 | **100%** | 4.05 | **推荐** |
| 0.50 | 100% | 5.69 | 可用 |
| 1.00 | 99.7% | 9.04 | 过拟合风险 |

### Length Normalization
- Normalized loss: 0.046 vs Unnormalized: 0.081
- **42%** 降低, 对变长 response 场景重要

### DPO vs PPO 对比
| | DPO | PPO |
|---|-----|-----|
| 模型数 | 2 | 4 |
| 内存开销 | ~2x | ~4x |
| 训练复杂度 | 简单分类 | RL 循环 |

## 05:30 — Transformer 数学基础 + MoE 架构 + verl GRPO 源码

### Transformer 数学基础
- 从第一性原理推导 Self-Attention, Softmax, LayerNorm/RMSNorm 的反向传播
- FLOPS = 6ND 的推导: 前向 1x + 反向 2x = 3x per param per token
- Attention 反向: dL/dS = A*(dL/dA - sum(dL/dA * A)) → FlashAttention 利用在反向重算
- KV Cache 数学: 7B GQA(8) → 4KB/tok/layer, 32层×4096tok×32batch = 16GB
- 笔记: `notebook/fundamentals/transformer-math-fundamentals.md`

### MoE 架构深度解析
- Dense vs Sparse: 计算∝激活参数, 不∝总参数
- Router: Top-K 选择 + Auxiliary Loss 负载均衡
- DeepSeek-V3: 671B/37B = 18x 稀疏, 256 routed + 1 shared expert
- EP (Expert Parallelism): All-to-All 通信, 需要 NVLink/InfiniBand
- 推理挑战: memory-bound 更严重, 需要 expert offloading 或 EP

## 06:30 — Triton Kernel Benchmark (RTX 4090)

**工具**: `tools/triton_kernel_benchmark.py` — Triton GPU kernel 基准测试

**核心发现**:

### Triton RMSNorm: 1.8x 加速
- 融合 mean→pow→rsqrt→mul 为 1 个 kernel launch
- 256-4096 维度稳定 1.8x 加速

### Triton Softmax: 0.3x (更慢!)
- PyTorch softmax 使用 NVIDIA 高度优化的 cuDNN kernel
- 自定义 Triton 无法超越 NVIDIA 工程师的手写 kernel
- **教训**: 不要盲目写自定义 kernel

### QKV Stacked: 2.0x 加速
- 3 次独立 matmul → 1 次 stacked matmul
- 减少 kernel launch 开销 + 更好的 GPU 利用率

### LayerNorm vs RMSNorm: LN 快 2.6x
- cuDNN LayerNorm 高度优化, 朴素 PyTorch RMSNorm 需要 3 次 launch
- Triton RMSNorm (0.028ms) 接近 cuDNN LayerNorm (0.019ms)

### Memory Bandwidth: 945 GB/s = 93.7% peak
- RTX 4090 理论 1008 GB/s, 实测 945 GB/s
