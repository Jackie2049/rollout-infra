## 00:20 — 新增 DPO 直接偏好优化笔记 (260 行)

DPO 是 RLHF 的简化替代方案，核心洞察是通过 Bradley-Terry 偏好模型的闭式解，把 Reward Model 和 RL 循环完全跳过——只需要偏好对数据 (prompt, chosen, rejected) 就能直接优化策略。DPO loss 本质上是在增加 chosen 回复概率的同时降低 rejected 回复概率，且隐含了 KL 约束。工程优势显著：四模型变两模型，不需要推理引擎集成，超参数从 6+ 减到 2 个（β 和 lr）。笔记还覆盖了变体 IPO（更保守的偏好模型）、KTO（不需要配对数据）、ORPO（去掉 Reference Model）、SimPO（用 length-normalized log prob 替代 π_ref）和 Online DPO（动态生成数据）。趋势：对齐方法在持续简化，但复杂推理任务仍可能需要 PPO/GRPO 的 token 级信用分配。

## 00:15 — 新增 Tokenizer 与推理管线笔记 (260 行)

Tokenizer 是推理管线中经常被忽视但实际影响很大的一环。笔记覆盖了 BPE 工作原理（从字节级逐步合并高频子串）、词表大小趋势（从 GPT-2 的 50K 到 Gemma 的 256K）、以及词表大小对推理的实际影响。最重要的发现是：更好的 tokenizer 直接降低推理成本——LLaMA-3 的 128K 词表让中文推理 token 数减少约 50%，这意味着 KV Cache 显存和推理延迟都减半。大词表的代价是 Embedding 层显存增加（LLaMA-3 的 Embedding 1GB vs LLaMA-2 的 256MB），但相对于整体推理收益，这个代价是值得的。

## 00:20 — 新增 LoRA / PEFT 笔记 (287 行)

LoRA 是参数高效微调的标配方法，用低秩矩阵分解 (ΔW = B×A, r << d) 让微调只需训练 0.1-1% 的参数。笔记覆盖了核心原理（秩选择 r=8-16 对大多数任务足够）、推理优化（权重合并后零额外开销）、多 LoRA 服务（一个基座服务多个 adapter，vLLM/SGLang 原生支持）、QLoRA（NF4 量化+LoRA 让 7B 模型在消费级 GPU 微调，显存仅 ~6GB）、以及 LoRA-RLHF（共享基座+独立 LoRA adapter，RL 训练显存从 240GB 降到 ~14GB+20MB）。关键洞察：LoRA 的零推理开销是它胜过其他 PEFT 方法的杀手锏——合并后与原始模型完全相同。

## 00:25 — 新增推理性能估算工具 inference_estimator.py

创建了一个 LLM 推理性能估算工具，支持 6 种预定义模型（LLaMA-7B/70B、LLaMA3-8B/70B、Qwen-72B、Mistral-7B）和 6 种 GPU（A100/H100/H200/A16/L40S）的推理性能估算。可以计算显存分配（模型权重+KV Cache）、最大 batch size、prefill/decode 延迟、理论吞吐量。支持 GPU 对比和模型对比模式。有趣发现：Mistral-7B 用 MQA（1 KV head）使 KV Cache 只有 16 KB/token（vs LLaMA-7B 的 512 KB），单 A100 吞吐接近 30K tok/s。
