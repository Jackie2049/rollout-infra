## 17:40 — Fused RMSNorm Backward CUDA Kernel 实现

### Python Fallback Backward Bug 修复

发现并修复 Python fallback backward 的关键 bug:
- **Bug**: `grad_input = grad_output * weight * inv_rms + grad_output - x_norm * coeff` 中 `+ grad_output` 是错误的
- **原因**: `y = x_norm * w + r` 中, `x` 只通过 `x_norm * w` 路径出现, residual 分支不贡献 `d_x`
- **修复后公式**: `d_x = inv_rms * (dy * w - x_norm * mean(dy * w * x_norm))`
- **验证**: FP32 backward correctness ALL PASS (dx_diff < 1.43e-6, cos_sim = 1.0)

### CUDA C++ Backward Kernel 实现 (v5)

新增 6 个 backward kernel (FP32/FP16/BF16 × add/norm):
- **设计**: 1 warp/row, 3-pass (inv_rms→dot/dw/dr→dx), atomicAdd for dw, FP32 accumulation→dtype convert
- **数学**: `d_x = inv_rms * (dy*w - x_norm*coeff)`, `d_r = dy`, `d_w = Σ(dy*x_norm)`
- **Host**: `fused_rms_norm_add_backward` 返回 (dx, dr, dw), `fused_rms_norm_backward` 返回 (dx, dw)
- **编译**: RTX 4090, sm_89, `python setup.py build_ext --inplace`

### vLLM V1 Scheduler 深度阅读

- **核心**: unified token budget — 无"prefill phase"/"decode phase"分离, 每请求只有num_computed_tokens
- **RUNNING优先**: decode请求优先分配budget, WAITING仅在无preempt时调度 → decode不被prefill阻塞
- **Preemption**: KV不足时preempt RUNNING→PREEMPTED→WAITING, free KV+recompute; FCFS抢最新/PRIORITY抢最低优先
- **WAITING调度失败**: 不preempt running → 直接break (prefill不抢占decode KV)
- **Chunked prefill**: long_prefill_token_threshold限制每步新prefill token数
- **Prefix cache**: get_computed_blocks() → 减少新token数 → 节省KV分配+计算
- **KV Connector**: WAITING_FOR_REMOTE_KVS → 等远程KV transfer完成
- **Cascade**: get_num_common_prefix_blocks() → 触发cascade attention条件
- **LoRA限制**: max_loras防止同时活跃过多LoRA
- **vs SGLang**: vLLM unified更灵活(同步prefill+decode), SGLang RadixAttention更灵活(无block对齐)

## 23:00 — AI Alignment 理论深度: RLHF → DPO → GRPO

### 统一数学框架

- 所有方法基于同一个目标: max E[r] - β KL(π_θ || π_ref)
- 闭式最优解: π* = (1/Z) π_ref exp(r/β) → **策略本身就是reward model**!

### DPO核心推导

- 反转最优策略 → 隐式reward: r(x,y) = β log(π*/π_ref) + β log Z(x)
- **Z(x)在偏好对比较中消除** → DPO直接优化: σ(β log(π(y_w)/π_ref(y_w)) - β log(π(y_l)/π_ref(y_l)))
- 1步pipeline, 2个模型, 无RL → 简单稳定

### GRPO核心: 组相对优势

- Ā_i = (r_i - mean_group) / std_group → 组均值替代critic/V函数
- 理论解释: baseline减方差 + 对比学习 + Leave-One-Out
- outcome-only reward → 推理自然涌现(DeepSeek-R1-Zero)

### 三方等价性

- DPO隐式reward = PPO显式reward (在最优解处)
- GRPO组baseline ≈ GAE V函数的蒙特卡洛估计
- 三者都是KL约束优化的不同实现方式

- 笔记: `alignment-theory-rlhf-dpo-grpo.md`

### RL Theory for LLM Training — 数学推导深度笔记

完整推导PPO/GRPO/DPO三大对齐算法:

1. **Policy Gradient基础**: ∇J = E[∇logπ(a|s)·R], baseline减方差(E[∇logπ·b]=0证明)
2. **PPO**: clip(rho·A,1-ε,1+ε)防止catastrophic update, GAE advantage, 4模型

4. **DPO**: 5步推导 → 隐式reward=β log(π/π_ref)+β log Z → Bradley-Terry模型 → Z(x)在差值中消去 → 1模型offline
5. **数学等价性**: 三者都优化max E[r]-β KL(π||π_ref) → 不同解法(在线/离线, critic/no-critic)

### prefix-0501 E2E Reuser精度Gap根因分析 — 关键发现!

**根因确认**: `run_ps_e2e.py` 使用 `VerlQwen3_6Integration`(两遍PS)但只做一次前向 → 每层attention都走prefix pass(存储KV但不注入suffix) → reuser的suffix tokens永远没有prefix KV → cos_sim 0.985而非0.999999

**两遍PS架构理解**:
- `VerlQwen3_6Integration` 设计为两遍:
  1. **Prefix pass** (store无KV): 正常attention → 存储KV → 返回输出
  2. **Suffix pass** (store有KV): 加载prefix KV → expand → concat → `flash_attn_varlen_func(causal=True)` → block-causal mask
- 单次前向中每层只有1次调用 → slot_id含layer_id → 每层新slot → 都走prefix pass → suffix pass永不执行

**`flash_attn_varlen_func(causal=True)` 的block-causal语义**:
- Q_len < KV_len 且 causal=True → Q[0]可见KV[0..prefix_len](所有prefix+第1suffix) → 这就是block-causal mask!
- 与我们的 `_causal_q_kv_mask` 数学等价 → 但用FlashAttention实现更快

**正确方案**: `run_ps_e2e_twopass_v2.py` — 两次独立前向(Pass 1: provider prefix → Pass 2: all suffix + KV/state injection) → DeltaNet还需要initial_state+conv1d overlap injection

**替代方案**: `MegatronAttentionIntegration`+`TorchReferenceBackend` 支持单遍PS(逐序列处理provider/reuser) → 但不支持verl model classes → 不适用于Qwen3.6-27B

- 笔记: `notebook/projects/prefix-0501-reuser-precision-gap-analysis.md`

2487行源码分析: 双注册表架构(14种Advantage Estimator + 10种Policy Loss)

**关键发现**:
1. **GRPO advantage**: `scores = rewards.sum()` → outcome-only; 组归一化 `(r-μ)/σ`; Dr.GRPO选项(不除σ)
2. **GRPO_VECTORIZED**: Python循环→torch向量操作 → 大batch加速
