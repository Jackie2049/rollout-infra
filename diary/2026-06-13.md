## 12:00 — RDMA + AI Cluster Networking架构深度分析

### 背景

继续ZeRO深度分析后的学习。GPU服务器仍然离线。从RDMA基础(rdma-networking.md已有975行参考)出发，深入分析Verbs内核机制、RoCE v2包封装、集群拓扑、拥塞控制算法。

### 核心

RDMA = 内核旁路+零拷贝 + 网络拓扑决定通信效率 + 拥塞控制保证无损

关键发现:
- **QP State Machine**: RESET→INIT→RTR→RTS→ERROR 5步 → INIT只recv → RTR可recv远端 → RTS可send → 连接建立!
- **Doorbell机制**: ibv_post_send→用户态写WQE→doorbell(MMIO)→NIC DMA执行 → 全程零syscall! → 这就是内核旁路的核心
- **CQE 64B格式**: status+opcode+byte_len+qp_num → NIC DMA写入 → 用户态ibv_poll_cq轮询 → 延迟≈0.5μs!
- **SRQ共享接收**: N个QP共享1个SRQ → M buffer vs N² buffer → 内存省+简化管理
- **RoCE v2封装**: IB传输头+UDP(IP port 4791)+IP+Ethernet → 可路由 → vs IB原生LRH(LID路由)
- **Lossless Ethernet三要素**: PFC(802.1Qbb优先级暂停)+ECN(RFC 3168拥塞标记)+DCQCN算法 → 必须全部配置!
- **PFC vs IB Credit**: PFC可能head-of-line blocking+deadlock → IB Credit原生无损 → 简单但贵!
- **Fat-Tree拓扑**: 2层(leaf+spine)≤64节点 → 3层(leaf+spine+core)>64节点 → 多路径负载均衡!
- **Rail-aligned**: GPU_i↔NIC_i → 8 rails → 每rail独立AllReduce → 8x带宽聚合 → Meta/Azure方案!
- **DCQCN算法**: Rate=Rate×(1-α/2) → α=ECN比例 → CNP反馈 → Fast/Active/Hyper三阶段恢复 → 类DCTCP但RDMA定制!
- **NCCL IB Plugin**: ibv_post_send→RDMA Write→GPUDirect→DMA-BUF → Socket Plugin(TCP fallback) → RTX 4090只能用Socket!
- **真实集群**: Meta 16K GPU 3层fat-tree+8 rails → Azure HBv3 8×A100+8 IB → AWS EFA SRD(自研可靠传输)
- **RTX 4090**: 无RDMA+无NVLink+无IB → 只PCIe+TCP → AllReduce 2.76GB/s → 单GPU最优!
