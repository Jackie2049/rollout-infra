## 23:50 — vLLM V1 KV Cache Architecture Source Reading

### 背景

续接session。GPU服务器仍然离线(SSH超时)。继续vLLM V1源码阅读。

### 核心发现: vLLM V1 KV Cache = 多类型协同管理!

旧V0: 单一KV cache类型 → 所有层共享一个block table → 简单但不支持混合模型

V1新架构: KVCacheSpec 9种 → KVQuantMode 5种量化 → 3种Coordinator → 可插拔Registry

**KVCacheSpec 9种类型层级**:
- FullAttentionSpec (标准) → TQFullAttentionSpec / MLAAttentionSpec / HiddenStateCacheSpec / SinkFullAttentionSpec
- SlidingWindowSpec → SlidingWindowMLASpec
- ChunkedLocalAttentionSpec
- MambaSpec (SSM state cache)
- CrossAttentionSpec / EncoderOnlyAttentionSpec

**KVQuantMode 5种量化**:
- NONE → FP8_PER_TENSOR → INT8_PER_TOKEN_HEAD → FP8_PER_TOKEN_HEAD → **NVFP4** (Blackwell FP4!)

**NVFP4 KV Cache Layout** (Blackwell下一代量化):
- Packed layout: fp4 data (head_size//2 bytes) + fp8 block scale (head_size//16 bytes)
- 7B: ~10KB/tok → 4x KV省 → 但RTX 4090不支持(SM89)

**MLA KV Cache Layout** (DeepSeek-V3/V4):
- DeepSeek-V4: 448B NoPE + 128B RoPE + 8B fp8 scale = **584B/tok**
- V3.2: kv_lora_rank=512 + qk_rope_head_dim=64 = **656B/tok**
- compress_ratio → storage_block_size更小但block_size不变

**3种Coordinator**:
- KVCacheCoordinatorNoPrefixCache → UnitaryKVCacheCoordinator → HybridKVCacheCoordinator
- **HybridKVCacheCoordinator**: 迭代固定点算法 → 跨组协调前缀匹配 → 收敛保证(长度单调递减)

**Manager dispatch** (关键发现!):
- MLAAttentionSpec → **FullAttentionManager** (不是特殊manager!)
- → MLA的block管理逻辑同FullAttention → 特殊逻辑在FlashMLA kernel层面
- SinkFullAttentionSpec → **SinkFullAttentionManager** (Sink需要特殊处理!)

**可插拔Spec Registry**:
- @register_kv_cache_spec → out-of-tree可以注册自定义spec → 不改vLLM核心代码!
- uniform_type_base_spec → 决定KV cache分组 → MLA归入FullAttention组

**Admission Cap** (防死锁):
- SWA/ChunkedLocal → max_admission_blocks_per_request → 防止过度预留 → startup+runtime同一真相源

**EagleProposer** (23行):
- 仅pass_hidden_states_to_model=True → 所有逻辑继承基类

**DraftModelSpeculator** (225行):
- 独立draft模型 → 自己的input_buffers, block_tables, kv_cache_config
- draft_logits → [max_num_reqs, num_spec_steps, vocab_size] → 概率draft采样
