## 23:45 — 向用户讲解 GPU kernel 合并和 FlashAttention tiling

用户追问了两个问题：(1) 什么是"合并成一个 GPU kernel"——GPU kernel 是一段 GPU 程序，每次 CPU 启动一个 kernel 有 5-20μs 开销，而且中间结果要写回显存(HBM)再读出。合并成一个 kernel 就是让 GPU 内部一次完成所有步骤，中间结果留在 GPU 快速缓存(SRAM)里不回写显存。(2) 怎么合并的——FlashAttention 用 tiling（分块）技术把 Q/K/V 切成小块放进 SRAM，然后用 "online softmax" 增量计算法让 softmax 可以和前面的矩阵乘法合并。传统方法需要先算完所有 Q×K^T 再做 softmax（需要全局 max 和 sum），但 online softmax 通过 running_max 和 running_sum 实现逐块更新，不需要等所有数据。这让显存从 O(N²) 降到 O(N)，速度提升 2-4x。

## 23:35 — HuggingFace 推理实验完成

在 A16 上用 HuggingFace transformers 跑了 GPT-2 推理测试（4.1M 参数小模型）。Forward pass 在 seq_len 64-512 都只需 2.9ms，显存仅 0.03GB。但自回归生成只有 11 tokens/s，因为 HuggingFace 的 generate() 每生成一个 token 都要重新计算整个序列的 attention，没有复用之前的 KV Cache。这也说明了 vLLM 的 PagedAttention + KV Cache 复用的价值——推理引擎通过缓存已计算的 Key/Value 矩阵避免重复计算，实际生产中可以达到数千 tokens/s。vLLM 安装因 PyTorch 版本兼容问题仍在解决中。

## 23:25 — 向用户讲解 SDPA Attention 概念

用户问到 SDPA（Scaled Dot-Product Attention）是什么。SDPA 就是 Transformer 中最核心的注意力计算：Attention(Q,K,V) = softmax(Q×K^T/√d) × V。其中 Q×K^T 计算 token 间关注度，除以 √d 做缩放防止梯度消失，softmax 归一化为概率，最后用概率加权 Value。PyTorch 2.0 提供了 `F.scaled_dot_product_attention()` 融合实现，自动选择 FlashAttention 等最优算法。我们的基准测试中 SDPA 在 bs=1 seq=4096 时耗时 5ms，内部自动利用了 FlashAttention 的 O(n) 显存优化。

## 23:20 — 向用户讲解 FP16 GEMM 概念

用户问到 FP16 GEMM 测试是什么。GEMM (General Matrix Multiply) 就是矩阵乘法 C=A×B，是神经网络最基本的运算（全连接层、Attention 的 Q×K 计算都是矩阵乘法）。FP16 是 16-bit 半精度浮点数，比 FP32 (32-bit) 省一半空间。关键区别在于 NVIDIA GPU 有专用的 Tensor Core 硬件单元来加速 FP16 矩阵乘法，一次可处理 8×8 矩阵块，而 FP32 只能走普通 CUDA Core。这就是为什么我们的测试中 FP16 达到 14.64 TFLOPS 而 FP32 只有 2.54 TFLOPS——Tensor Core 让 FP16 快了约 5.8 倍，这也是现代 AI 训练几乎都用混合精度的原因。

## 22:50 — vLLM V1 Prefix Caching 源码深度分析完成

后台 agent 完成了对 vLLM V1 架构下 prefix caching 机制的完整分析。核心发现：每个 KV Cache block 的 hash 通过链式结构计算（parent_hash + tokens + extra_keys），形成 Merkle-like 哈希链。四种 attention 类型有不同的 cache hit 检测策略，其中 FullAttention 从左到右线性扫描，SlidingWindow 从右到左搜索。Block 生命周期为 allocate → hash → cache → reuse(touch) → free → evict。分析结果保存为 `notebook/projects/vllm-prefix-caching-v1.md`。
