# MTP Training + Speculative Decoding (RTX 4090)

> 2026-06-05 | 工具: `tools/mtp_train_experiment.py` | RTX 4090 24GB
> 参考: DeepSeek-V3 (arXiv:2412.19437, Section 2.5)

## ⚠️ 负面结果

**MTP 在小规模合成数据上无明显收益** — 与 DeepSeek-V3 的正面结果形成对比。

## 1. 训练收敛对比

| 方法 | 最终 main loss | vs Standard | 参数量 | 模式匹配 |
|------|---------------|-------------|--------|---------|
| Standard | 5.2929 | baseline | 1.08M | 5% |
| MTP depth=1 | 5.2994 | -0.12% | 1.40M (+29.6%) | 5% |
| MTP depth=2 | 5.3349 | -0.79% | 1.73M (+59.2%) | 5% |

**MTP 无显著改善, depth=2 反而略差**

## 4. 原因分析

### 为什么 MTP 在小规模无效?

1. **数据太简单**: 合成重复 pattern, 不需要 "multi-token planning"
2. **模型太小**: 1M 参数 vs DeepSeek-V3 671B, 表达能力不足
3. **训练不充分**: 500 steps, model 没充分收敛 (loss ≈ 5.3, 仍远高于理想)
4. **MTP 的信号太弱**: 权重 0.3 的辅助 loss 对主 loss 几乎无影响

### DeepSeek-V3 为什么有效?

1. **14.8T tokens 多样数据**: MTP 提供的 "前瞻" 信号在复杂数据中有价值
2. **671B 参数**: 模型有足够容量同时优化多个目标
3. **充分训练**: 数万亿 tokens 充分利用了 MTP 的额外梯度信号
4. **MTP 作为 spec decoder**: 在大模型上, MTP 模块预测准确率 >80% (vs 我们 0%)

### 教训

1. **规模很重要**: 许多技术只在足够规模时才有效
2. **负面结果有价值**: 理解了 MTP 不 work 的条件
3. **MTP 的价值在于推理加速**: 训练改善是次要的, spec decode 才是主要卖点
4. **验证需要真实模型**: 小模型 + 合成数据无法验证 LLM 级别的技术
