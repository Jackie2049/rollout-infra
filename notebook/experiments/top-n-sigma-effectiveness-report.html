Top-nσ Logit Truncation: Algorithm Effectiveness
and Vectorized Implementation Verification

Experiment Report for vLLM PR #7 — Top-nσ Custom Logits Processor
NVIDIA RTX 4090 24GB · CUDA 12.8 · PyTorch 2.9+cu128
Reference: Tang et al., “Top-nσ: Not All Logits Are You Need”, ACL 2025. arXiv:2411.07641
Abstract. This report presents a comprehensive verification of the Top-nσ logit truncation algorithm and its vectorized implementation for vLLM. Top-nσ filters logits in logit-space using a threshold derived from the distribution's standard deviation: threshold = max(logits) − n × std(logits). We verify five properties: (1) the Gaussian tail assumption underlying the algorithm, (2) adaptive candidate set sizing based on distribution sharpness, (3) temperature-invariant candidate counts — a property unique to logit-space methods, (4) argmax invariance guaranteeing greedy decoding safety, and (5) bit-for-bit equivalence between the vectorized and original row-by-row implementation. All experiments were conducted on an NVIDIA RTX 4090 with vocab sizes up to 128K. The vectorized implementation achieves 10.3×–65.7× speedup over the row-by-row loop while producing identical output across all tested configurations.

1. Introduction

Top-nσ (Tang et al., 2025) is a logit-space dynamic truncation method for LLM sampling. Unlike probability-space filters such as top_p and min_p, which operate after softmax, Top-nσ filters logits before softmax, using the standard deviation of the logit distribution to determine the cutoff threshold:

threshold = max(logits) − n × std(logits);   logits[logits < threshold] = −∞

The key insight is that the tails of LLM logit distributions are approximately Gaussian. Under this assumption, a threshold at n standard deviations below the maximum corresponds to a well-defined percentile of the distribution, enabling principled filtering that adapts to distribution “peakiness” without requiring temperature tuning.

This report verifies the algorithm's theoretical claims and the correctness of its vectorized implementation in vLLM PR #7.

5. Experiment 3: Temperature Invariance

This is the most distinctive property of Top-nσ. Probability-space filters (top_p, min_p) are applied after softmax, so temperature scaling radically changes their behavior. Top-nσ operates before softmax, and because threshold = max(logits)/T − n × std(logits)/T = (max(logits) − n × std(logits)) / T, temperature cancels out from the filtering decision.

7. Experiment 5: Edge Case Handling

We test four edge cases to ensure the implementation handles pathological inputs gracefully:

NaN/Inf rows are skipped because torch.isfinite().all() returns False. Constant rows are skipped because std == 0 prevents meaningful threshold computation. Both behaviors are mathematically sound: there is no principled filtering decision when the distribution is degenerate.

11. Conclusions

  1. Gaussian tail assumption verified: Logit kurtosis is within 0.06 of the Gaussian reference (3.0) across all distribution shapes.
  2. Adaptive candidate sizing verified: Top-nσ automatically retains more tokens when the model is uncertain and fewer when it is certain, without requiring manual threshold tuning.
  3. Temperature invariance verified: Candidate count is constant across T=0.1–10.0, while top_p varies by 19,665× and min_p by 20,000×. This is a unique property of logit-space filtering.
  4. Argmax invariance verified: The greedy token is preserved in all 32 tested configurations, guaranteeing no impact on greedy decoding.
  5. Edge cases handled correctly: NaN/Inf, zero std, empty inputs, and mixed scenarios are all handled gracefully with mathematically justified skip logic.
  6. Vectorized implementation is correct: Bit-for-bit identical to row-by-row across 20 standard configs and 5 edge cases, with 10–65× performance improvement.
  7. n=2.0 recommended default: Preserves ~2–3% of vocab, comparable to moderate top_k/min_p settings, with the advantage of automatic adaptation.
