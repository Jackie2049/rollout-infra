# KV Cache Compression 实测 (RTX 4090)

> 2026-06-05 | 工具: `tools/kv_cache_compress.py` | RTX 4090 24GB

## 1. 实验设计

4 种 KV Cache 压缩方法 + 5 个实验:
1. **量化** (FP16 → INT8/INT4)
2. **Token 剪枝** (基于 attention 重要性)
3. **滑动窗口** (只保留最近 W 个 token)
4. **组合压缩** (剪枝 + 量化)

## 2. 量化精度

| 方法 | Max Error | Mean Error | Cos Sim | 内存节省 |
|------|-----------|------------|---------|---------|
| INT8 | 0.0066 | 0.000485 | **0.999963** | 50% |
| INT4 | 0.129 | 0.00887 | 0.987927 | 75% |
| Per-head INT8 | 0.0114 | 0.000797 | 0.999901 | 50% |

**关键发现**:
- **INT8 几乎无损**: cos_sim=0.9999, max_err=0.007 → 生产环境完全安全
- **INT4 有损**: cos_sim=0.988, max_err=0.129 → 质量下降可感知
- Per-head INT8 比 per-tensor 稍差 (因为量化粒度更大)

## 3. Token 剪枝

| 保留比例 | Max Error | Cos Sim |
|---------|-----------|---------|
| 25% | 1.030 | 0.536 |
| 50% | 0.439 | 0.740 |
| 75% | 0.426 | 0.884 |
| 90% | 0.263 | **0.958** |

**分析**:
- 50% 剪枝: cos_sim=0.74 → 质量损失大!
- 需要 ≥75% 保留才能保持 cos_sim>0.88
- 随机数据剪枝效果差 (无语义结构) → 真实数据有 locality, 剪枝效果会更好
- 挑战: 需要 attention score 才能做 oracle 剪枝

## 4. 滑动窗口

| Window | Max Error | Cos Sim |
|--------|-----------|---------|
| 64 | 1.532 | 0.349 |
| 128 | 0.931 | 0.492 |
| 256 | 0.579 | 0.698 |
| 384 | 0.388 | **0.864** |

**分析**: 滑动窗口质量损失 > token 剪枝 (剪枝选择重要的保留, 窗口只保留最近的)
- Mistral SW-4K: 节省 97% 内存, 但需要局部性假设
- 长距离依赖任务 (如文档 QA) 不适合滑动窗口

## 5. 7B 模型 / 128K 上下文内存

| 配置 | KV Cache (GB) | 节省 |
|------|--------------|------|
| FP16 | 17.18 | baseline |
| FP32 | 34.36 | -100% (更大) |
| INT8 | 8.59 | 50% |
| INT4 | 4.29 | 75% |
| SW-4K | **0.54** | **96.9%** |
| SW-8K | 1.07 | 93.8% |
| SW-16K | 2.15 | 87.5% |

**关键**: SW-4K 仅 0.54GB! 从 17.18GB 降到 0.54GB

## 6. 组合压缩

| 方法 | Max Err | Cos Sim | 压缩比 |
|------|---------|---------|--------|
| 75%+INT8 | 0.425 | 0.884 | 2.7x |
| 75%+INT4 | 0.428 | 0.874 | 5.3x |
| 50%+INT8 | 0.438 | 0.740 | 4.0x |
| 50%+INT4 | 0.524 | 0.731 | 8.0x |

**最佳权衡**: 75%保留 + INT8 → 2.7x 压缩, cos_sim=0.884

## 7. 核心学习

1. **INT8 量化是最安全的**: cos_sim=0.9999, 50% 节省, 推荐所有场景
2. **INT4 有风险**: max_err=0.13 可能影响输出质量
3. **Token 剪枝需要智能策略**: oracle 剪枝效果比滑动窗口好
4. **滑动窗口依赖局部性**: 适合生成任务, 不适合长距离依赖
5. **7B/128K 的 KV cache = 17GB**: 超模型权重! KV cache 压缩是必需的
6. **SW-4K 是暴力但有效**: 97% 节省, Mistral 的成功验证了这条路
7. **生产推荐**: INT8 + 选择性剪枝 (不是全量剪枝)
