# DAPO vs GRPO 宎战对比 — 前沿RL算法在小模型上的验证

> 2026-06-07 | RTX 4090实测: 将DAPO和Dr.GRPO的4项改进应用到mini GRPO pipeline, 对比原始GRPO

## 概述

基于DAPO(arXiv 2503.14476)和Dr.GRPO(arXiv 2503.20783)的前沿论文分析, 我们将4项改进应用到mini GRPO训练pipeline, 并与原始GRPO进行300步对比实验。

## 实验设计

**任务**: 算术 a+b= (a,b∈{0..4}), vocab=20
**模型**: MiniGQATransformer 76,928 params (hidden=64, 2 layers, GQA-4:2)
**Reward**: 1.0(正确), 0.3(±1), 0.1(±2), 0(其他)
**设置**: RTX 4090, 300步, n=8, lr=1e-3, 8 prompts/step

## DAPO 4项改进实现

### 1. 全局归一化 (Dynamic Advantage Normalization)

**原始GRPO**: 组内归一化 advantage = (r - μ_group) / σ_group
→ 不同难度组的advantage尺度不一致 → 梯度不稳定

**DAPO**: 跨batch全局归一化 advantage = (r - μ_global) / σ_global
- μ_global = 全batch所有response的平均reward
- σ_global = 全batch的标准差
- **效果**: 不同难度组的advantage尺度一致 → 梯度稳定

### 2. 解耦clip (Decoupled Clip)

**原始PPO-clip**: ratio clip at [1-ε, 1+ε] → 对称clip
**DAPO**: ε_lower ≠ ε_upper → 不对称clip
- ε_lower=0.3 (允许更快降低坏动作概率)
- ε_upper=0.2 (保守增加好动作概率)
- **效果**: 模型更自由地修正错误, 同时保守地强化正确路径

### 3. 动态采样 (Dynamic Sampling)

**原始GRPO**: 固定n个response → 组内reward趋同时σ=0 → 无梯度
**DAPO**: 当组内reward std < 阈值时增加n
- 阈值: dynamic_sampling_min_std=0.05
- 最大n: 16 (初始n=8, 可增至2倍)
- **效果**: 避免零梯度的跳步问题 → 持续学习

### 4. Token-level Loss

**原始GRPO**: response-level loss → 长response贡献更多梯度 → 隐性鼓励冗长
**DAPO**: token-level loss → L = Σ_t(-advantage_t × log_prob_t) / Σ_t mask_t
- **效果**: 短长response贡献相同梯度量 → 不鼓励冗长

### 5. 序列级KL (Dr.GRPO)

**原始GRPO**: per-token KL penalty → 长response惩罚多 → 隐性鼓励简短
**Dr.GRPO**: 序列级KL → KL = β × Σ_t KL_t / num_tokens
- β=0.01 (小系数, 轻约束)
- **效果**: 短长response的KL惩罚公平 → 不偏向简短或冗长

### 训练稳定性分析

DAPO虽然能到达更高的peak, 但稳定性差:
- **前100步**: DAPO起步慢(0→42.7%), GRPO更快(1.6→60.9%)
- **中期(100-200步)**: DAPO到65%, GRPO在43-47%区间
- **后期(200-300步)**: DAPO到达96.7%peak但立即崩溃到12.5%, GRPO到87.5%peak终值75%

### 根因分析

**为什么DAPO峰值更高但不稳定?**

1. **全局归一化的副作用**: σ_global包含全batch的方差 → 当batch中有些组表现好有些组表现差 → σ_global较大 → advantage被压缩 → 梯度信号弱 → 但偶尔采样到恰好好分布 → advantage未被过度压缩 → 大幅更新 → peak
2. **动态采样的悖论**: 增加n → 更多同质化response → σ仍=0 → 即使n=16也无法打破同质性 → 小模型容量有限 → 对不同prompt倾向于输出相同digit
3. **小模型的根本限制**: 76K参数 → 无法同时记忆所有25个(a,b)组合的正确答案 → 偏向输出某个高频digit → 组内同质化

**与DAPO论文的对比**: DAPO在Qwen2.5-Max(大模型)上稳定有效, 但在小模型上, 动态采样和全局归一化反而引入不稳定 → **算法改进的效果依赖于模型容量**

**与之前GRPO对比**: 新GRPO实验(300步,n=8)peak=87.5%(比之前的59%高), 这是因为n=8比n=4探索更多, 8 prompts/step比之前的更多 → 之前GRPO实验配置不同

## 关键洞察

### 1. SFT暖启动仍然是最关键的

无论GRPO还是DAPO, 从随机开始训练都不如SFT暖启动 → **warm start比算法改进更重要**

### 2. DAPO在小模型上效果有限

DAPO的改进在大模型上有效, 但76K参数的mini模型:
- 动态采样无法打破模型同质化倾向
- 全局归一化引入跨组不稳定性
- **结论**: 算法改进需要足够的模型容量才能发挥效果

### 3. 熵坍塌是根本问题

DAPO论文指出熵坍塌 → 我们观察到: 模型趋向确定性输出 → 组内response相同 → 零梯度 → 即使动态采样也无法恢复多样性

### 4. 训练reward ≠ eval性能

DAPO的96.7%训练accuracy → 52%eval → 与PPO的87.5%训练→34%eval一致 → **采样reward不等于真实性能**

## 改进方向

1. **SFT→DAPO**: 先SFT暖启动, 再用DAPO改进GRPO → 预估可能从100%基础上进一步提高稳定性
2. **Entropy bonus**: 添加熵奖励防止策略坍塌 → DAPO论文也提到这个方向
3. **更大的n**: n=64(DeepSeek-R1级别) → 更多探索打破同质化
4. **更大模型**: 至少1M+参数 → 足够容量记忆25个组合

## 模型容量扩展实验 (RTX 4090)

### 关键发现: 更大模型GRPO反而更差!

| 模型 | Params | Peak Acc | Final Acc | Steps≥50% |
|------|--------|----------|-----------|-----------|
| 76K (hidden=64) | 76,928 | **87.5%** | 73.4% | 109/300 |
| 449K (hidden=128) | 449,280 | 87.5% | 12.5% | 70/300 |
| 2M (hidden=256) | 2,374,144 | 75.0% | 25.0% | 59/300 |
| 10M (hidden=512) | 9,466,880 | 75.0% | 12.5% | 34/300 |

**反直觉**: 更大模型peak accuracy更低(87.5%→75%), steps≥50%更少(109→34)!

### 根因: Reward信号与模型容量不匹配

1. **过拟合风险↑**: 更大模型 → 更多参数 → 更容易fit reward noise → 不稳定
2. **探索空间↑**: 更大模型 → 更多种可能的response → 组内更难有共识 → reward variance更大 → 梯度不稳定
3. **简单任务不需要大模型**: a+b=只有25个(a,b)组合 → 76K已经over-parameterized → 10M更是10x过剩

**类比**: 让数学教授算1+1 → 可能犹豫"是否需要更深入的分析" → 反而不如小孩直接说"2"

### 结论

1. **GRPO/DAPO改进需匹配任务难度**: 简单reward→小模型更好; 复杂reward→大模型才体现优势
2. **模型容量不是唯一瓶颈**: Reward signal的复杂度才是关键 → 两者需要同步增长
3. **DeepSeek-R1用7B+MoE+复杂reward**: 任务难度和模型容量匹配 → 成功
4. **我们的76K模型+简单reward**: 刚好够用 → 10M模型+简单reward → 过剩 → 反而更差
