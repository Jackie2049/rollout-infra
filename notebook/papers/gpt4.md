# Paper Reading: GPT-4 Technical Report

> OpenAI, 2023 | arXiv: 2303.08774
> 精读日期: 2026-06-05
> 优先级: P0 (大模型能力的里程碑)

## 1. 论文概要

**核心贡献**:
1. **可预测的扩展性** (Predictable Scaling): 用 1/1000~1/10000 计算量的小模型精确预测大模型性能
2. 大幅超越 GPT-3.5 的多维度能力 (MMLU 86.4%, HumanEval 67%)
3. RLHF 安全对齐工程实践 (RBRMs + 红队测试)

**刻意不公开**: 模型架构、参数量、训练数据、计算资源、训练方法

## 2. 可预测的扩展性

### 2.1 核心发现

```
从使用 1000x-10000x 更少计算量训练的模型,
可以准确预测 GPT-4 的最终性能!

意义:
  - 投入大规模计算前, 可以通过小实验预估最终能力
  - 避免浪费数百万美元的试错
  - scaling law 不只是理论, 是实用的工程工具
```

### 2.2 扩展定律

```
基本形式: L(C) = a · C^(-b) + c

  C = 计算量 (FLOPs)
  a, b = 幂律系数
  c = 不可约损失

能力预测 (如 HumanEval):
  -E_P[log(pass_rate(C))] = α · C^(-k)

  → 计算量直接映射到代码通过率!
```

### 2.3 训练中预测

```
从训练早期 (一小部分步数) 外推最终 loss:
  - 拟合训练曲线的幂律关系
  - 提前判断是否需要调整超参
  - 实际值与预测高度吻合

实践意义: 训练 1-2 天就能判断是否需要调整,
  而不是训完 100 天才发现配置错了
```

## 3. 基准测试表现

### 3.1 关键基准

| 基准 | GPT-4 | GPT-3.5 | 前SOTA | 提升 |
|------|-------|---------|--------|------|
| MMLU (5-shot) | **86.4%** | 70.0% | 75.2% (Flan-PaLM) | +11.2pp |
| HumanEval (0-shot) | **67.0%** | 48.1% | - | +18.9pp |
| GSM-8K (5-shot CoT) | **92.0%** | 57.1% | - | +34.9pp |
| Bar Exam | **90th%** | - | - | 人类 top 10% |

### 3.2 RLHF 对能力的影响

```
Base model: 73.7% (综合考试)
RLHF model: 74.0%

结论: RLHF 几乎无损 → 对齐 ≠ 能力下降!
这与 "alignment tax" 的担忧相反
```

## 4. 安全与对齐

### 4.1 RLHF 改进 (vs InstructGPT)

```
1. 预训练阶段: 改进数据过滤
2. RLHF 训练: 更多更高质量的人类反馈
3. 安全专项数据收集: 边界情况标注
4. RBRMs (Rule-Based Reward Models):
   - 零样本 GPT-4 分类器作为额外奖励信号
   - 基于规则的奖励补充人类偏好
   - 防止生成非法/有害内容
```

### 4.2 安全改进量化

| 指标 | GPT-4 vs GPT-3.5 |
|------|-------------------|
| 禁止内容响应 | **减少 82%** |
| 敏感请求适当处理 | **提升 29%** |
| 毒性输出 | 0.73% vs 6.48% |

### 4.3 红队测试

```
50+ 外部专家参与
领域: 生物风险、网络安全、偏见与公平性
结果反馈到安全训练
```

## 5. 已知局限性

```
1. 幻觉 (Hallucination):
   仍然会自信地生成错误信息
   → 不完全可靠, 不能盲目信任

2. 校准性受损:
   RLHF 使模型过度自信
   Base model 的置信度校准更好

3. 上下文窗口:
   8K tokens (另有 32K 版本)
   对长文档处理有限

4. 数据截止:
   训练数据截止 2021年9月
   不具备最新知识

5. 透明度不足:
   未公开架构/参数/数据
   引发开放科学讨论

6. 过度优化 (Over-optimization):
   奖励模型分数 ≠ 真实人类偏好
   Goodhart's Law: 当指标成为目标, 它就不再是好指标
```

## 6. 对 AI Infra 的启示

```
1. 可预测扩展 = 训练效率:
   小规模实验 → 预估大模型性能 → 节省计算成本
   → 需要完善的 benchmark pipeline

2. RLHF 工程化:
   GPT-4 用 RBRMs + 红队 + 专项数据
   → 对齐不只是算法问题, 更是工程问题
   → vLLM/SGLang 的 RLHF serving 需要支持这类 pipeline

3. 多模态推理:
   图像+文本输入 → 推理需要处理多模态
   → vLLM 的 encoder_runner + vision 处理

4. 安全是系统工程:
   不仅仅是 RLHF, 还需要 RBRMs + 红队 + 数据过滤
   → AI Infra 需要支持整个安全 pipeline
```

## 7. 核心学习

1. **Scaling 是可预测的**: 1/1000 计算量就能预测, 这是工程上最有价值的发现
2. **RLHF 几乎无损**: 73.7% → 74.0%, 对齐 ≠ 能力下降
3. **安全是工程问题**: RBRMs + 红队 + 专项数据, 不仅是算法
4. **过度优化是永恒风险**: Goodhart's Law 适用于所有代理指标
5. **幻觉仍未解决**: 即使 GPT-4 也会自信犯错
6. **校准性被 RLHF 损害**: 过度自信是 RLHF 的副作用
7. **开放 vs 保密的权衡**: 技术报告的保密策略引发社区讨论
